# BB 复刻方法

## 先确定任务范围

确认用户提供的是：

- 完整参考视频；
- 一个片段；
- 关键帧；
- 已有工程；
- 已有观察记录。

已有工程和来源记录可用时，优先继续编辑。

参考只有图片时，可以重建静态棋盘和外观，但不能凭空声称还原了未观察到的动作、速度或声音。需要补全动作时，明确区分“复刻到的部分”和“新设计的部分”。

## 观察内容

按实际需要记录：

- 画布尺寸、棋盘位置和单格尺寸；
- 初始占格和颜色；
- 三个候选的形状、颜色和位置；
- 供给轮次及候选使用顺序；
- 拾取、拖动、释放和消除时刻；
- 每步落点及消除行列；
- 方块拖动轨迹和显示尺寸；
- 指针、背景、牌面、HUD、音效与音乐；
- 用户明确要求保留的特殊效果。

先抓玩法和时间，再细化画面。
不要为了快速有结果而把原视频的供给或动作替换成机器随机生成。

未知格子不等于空格；未看清的动作不等于没有动作。

## 测量和抽帧

当前实际脚本：

    python3 scripts/inspect-reference-video.py \
      "/实际路径/reference.mp4" \
      --output-dir "outputs/block-placement/<日期>/<任务>/reference/measurement" \
      --frames "0,15,30"

要求输出目录是新目录，不覆盖已有测量。

先查看 `--help`，按实际时长选择帧号。
脚本生成 `measurement.json` 和所选精确帧。

脚本提取帧不等于已经检查了帧。
Agent 仍须实际看图、观察连续运动；有声音要求时实际听相关片段。

当前测量和标注链以恒帧率视频为主。遇到 VFR 或异常时间戳，说明具体限制。若另行生成恒帧率工作副本，保留原片，并分别记录两个文件身份。

## 时间和坐标

不要混用三种量：

1. 源帧号；
2. 测量得到的秒数；
3. 输出帧号。

源帧转时间使用测量数据。
输出时钟由工程帧率决定。
不能简单把所有帧字段乘以同一个比例来冒充保持时长。

校准方块轨迹使用：

- 1080×1920 设计坐标；
- 方块包围盒左上角；
- 每个轨迹点自己的单格尺寸。

指针轨迹与方块轨迹是两种轨迹。
不能把手指中心直接当成方块左上角。

棋盘几何、候选三个横坐标以及源画面的 contain/cover/stretch 映射，要分别理解。修改源映射不意味着已有方块几何会自动正确移动。

释放位置需要与目标格对应。遇到不一致先检查：

- 锚点；
- 棋盘原点；
- 行列；
- 单格尺寸；
- 源画面映射。

不要用随意吸附掩盖错误的标注。

## 使用现有入口

页面入口是“参考视频观察记录”。

顺序按任务需要选择：

- 选择参考视频；
- 导入同源测量；
- 填写或导入结构化玩法标注；
- 填写并检查几何和方块轨迹；
- 按需加入图片、WAV 和指针；
- 生成完整作品包；
- 在当前工作台重开、预览和导出。

可以使用 Agent 分析辅助填写，但只有实际观察和核对过的内容才能标记为确认。

已有三步合成示例可用来理解格式，不可以把其动作、轨迹或帧号当成新视频的测量结果。

## 素材

优先用用户指定的实际图片和声音。

- 初次校准图片入口支持 PNG。
- 通用图片绑定入口支持当前实现接受的 PNG/JPEG。
- 工程音频以现有 WAV 消费者为准；PCM16 WAV 是稳妥的工作格式。
- 换成程序素材或测试音只在符合用户要求时使用，并说明与原片的区别。
- 参考中的纹理、文字、指针或特效若尚不支持，不要静默忽略后宣称完全复刻。

保留资源哈希及实际绑定。
图片存在于资源表，不代表画面已经使用它。

## 继续编辑复刻作品

从当前作品选择“修改复刻动作与几何”，载入同一源视频，再选择“继续编辑当前复刻作品”。

当前实现会恢复：

- 来源观察；
- 工程名称和身份；
- 当前图片；
- 完整混音；
- 已配置效果；
- 可恢复的指针信息。

继续编辑时使用恢复的作品模板，不把它重新当成空白初次生成。

目前恢复流程针对同一条来源 Take。
多 Take 或额外独立时间轨道超出支持范围时，指出具体条件；不删除这些数据来绕过检查。

## 复刻检查尺度

按用户要求看差异，不要求每个像素完全一致。

优先查看：

- 开场棋盘；
- 关键拖动和释放；
- 一次代表性消除；
- 结尾。

必要时播放一小段连续运动，检查跳变、错位和不自然停顿。

用户只要工程时，确认可编辑、可重开和必要的画面映射即可。
用户要视频时，再检查本次成片。

不要反复渲染未修改的历史样例。
记录实际发现的差异，能修复就修复；不能表达时交代限制。
