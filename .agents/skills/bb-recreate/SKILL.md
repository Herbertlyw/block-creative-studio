# BB 参考复刻

目标是交付用户指定范围的可编辑 BB 工程，以及用户要求的预览或视频。

参考视频需要由 Agent 或人实际观察、标注。当前工作台不会自动识别任意视频。已有观察记录可以帮助接续，但不能代替对新增或变更内容的观察。

## 开始与恢复

先读 [共用状态机](references/state-machine.md)。

- 新任务创建任务目录，记录来源、要求和终点。
- 已有任务先读 `task.json`，检查记录中的输入、当前工程和下一步。
- 已有可用复刻工程时，从该工程继续，不重新用默认模板覆盖。
- 用户只要求换图、换音乐等变体时，使用 [bb-variant](../bb-variant/SKILL.md)。

按需读取：

- [复刻方法](references/recreation-guide.md)：观察、坐标、时间、素材和继续编辑。
- [工作台能力地图](references/workbench-map.md)：当前入口、实际源码和功能限制。

不需要每次读完全部历史文档和冻结参考源码。

## 执行重点

1. 明确本次参考范围和终点：工程、预览或视频。
2. 实际查看参考，记录初盘、候选、落点、消除、时间和必要轨迹。
3. 使用现有标注、校准、素材和作品包入口生成工程。
4. 预览本次涉及的动作，修正有意义的偏差。
5. 保存并重开；用户要求视频时再导出。

生成结果必须保留可编辑玩法和资源引用。把原视频直接铺成背景、烧录为不可编辑视频或使用不匹配的默认动作，不能完成复刻要求。

不清楚的格子、动作或资源不能伪造为已确认。记录不确定点；能独立完成的部分继续做。只有影响关键结果且无法从现有资料判断时，才向用户询问。

## 继续编辑已有复刻

使用当前作品作为模板：

- 保留名称、素材、音频配置和用户没有要求修改的外观。
- 修改动作、时间或几何后，重新检查受影响的轨道。
- 不清空所有素材后从头装配。
- 不为了绕过限制删除来源、指针或其他 Take。
- 不能表达的特殊轨道按具体缺口处理，不笼统要求补整个源码仓库。

## 轻量检查

检查用户实际要求的终点：

- 工程：结构与玩法可用，依赖齐全，保存后可重开。
- 预览：查看相关关键帧和一小段连续动作。
- 视频：打开本次成片，确认主要动作、画面和要求的声音进入输出。

仅检查本次相关内容。没有音画异常时，不做采样级相关性测量；没有改代码时，不要求跑全套软件测试。

技术检查和用户审美认可分别描述。没有用户认可不必让一般交付一直停在等待审批。

## 交付

给出当前工程、用户要求的预览或视频，以及简短的已实现内容和剩余差异。

任务结果放在：

`outputs/block-placement/<日期>/<任务名>/`

建议按需使用 `projects/`、`previews/`、`videos/`、`reference/` 子目录。
保留原始输入和已有结果，不覆盖用户原件。

完成实际交付后，把任务推进到 `done`。不要只交一份计划就结束执行。
