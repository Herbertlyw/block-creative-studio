## 通用执行约定

### 文件与事务

1. 自动识别原生 V2 工程与 `bcs-bb-work` 作品包，并校验声明游戏与内容一致。拒绝未知格式，不擅自降级。
2. 先读取、解析和校验原件，再在副本执行操作；完成全部相关校验后才发布输出文件。
3. 编辑必须指定新的输出路径。首版拒绝覆盖输入及已有输出，检查路径别名；使用临时文件和不覆盖已有目标的原子发布方式，失败或取消不留下伪装成成品的文件。
4. 未修改字段、来源、指针、素材和绑定必须保留。报告中列出修改及失效的具体 Take、动作、效果或片段 ID，不能只返回泛化的“成功”。
5. 涉及 Take、棋盘、供给和时间的操作，必须处理受影响的片段哈希、校准、交互和特效绑定。默认拒绝无法保持有效性的编辑；显式删除／解绑另设操作，不自动清理来让校验通过。
6. 外部素材只从明确指定的输入或素材根目录解析，检查实际路径、字节和哈希；输出记录依赖，不能生成只能在开发者机器重开的工程。

### 发现、错误与运行环境

- 命令发现标明操作 Schema、版本、适用输入格式、运行环境、保护限制和已验证状态。底层存在但未接通的操作单独列为不可调用，不能让帮助信息误报可用。
- 首版统一成功和失败的 JSON 结果。沿用现有外层合同；结构化错误放在 `report` 中，补充错误码、字段、对象 ID 和可执行的修正说明，不另造冲突的结果格式。
- JSON 模式的 stdout 只输出机器可读结果；进度与诊断走 stderr。约定成功退出 0、操作失败 1、参数错误 2、主动取消 130，并测试退出码与结果一致。
- 查询、规则回放和纯工程编辑优先在 Node 执行。图片解码、画布和 WebCodecs 走实际浏览器；不使用空 DOM 对象或假成功补齐环境。
- Node CLI 单独构建，拟输出 `dist-cli/bcs.mjs`，提供 `npm run bcs -- …` 与指向构建入口的 bin。复用现有构建工具；阶段 0 验证 Node 依赖边界、别名及浏览器模块不会被查询命令意外启动。
- 第一版媒体命令面向本机已安装 Chrome 的环境；启动前检查浏览器和编码能力，缺失时明确报错。是否可独立安装发布，在构建与运行依赖验证通过前不作承诺。

## 验证与交付规则

只执行受影响范围的检查。新增 CLI 需覆盖构建后真实进程调用、退出码、JSON stdout、错误输入和文件原子性；涉及 BC 时跑 `npm run test:bc`，涉及 BB 作品包时跑其现有相关测试。源代码变更运行 typecheck 和 build；修改表单或播放器时补对应浏览器回归。

只有媒体阶段或实际影响媒体链的修改才导出短片。文件读取、文档或命令发现的改动不触发历史媒体重渲染。记录纯函数测试、浏览器真实运行、异步故障注入及人工观感各自的证据边界。

每批交付包含：完整 SHA、可用命令与明确限制、涉及文件、检查结果、输入保护证据、生成物路径和下一条可执行操作。生成物、真实作品、素材、原始交接和诊断放入忽略的 `outputs/`；源码、Schema、生成式测试和当前文档才进入 Git。

保留仓库私有状态、BB 全部现有能力、BC 原生 V2 / 0.4.0 / 30fps reference-2d 边界。main 合并单独处理；不强推、不关闭保护、不删分支。可先继续采用独立分支交付，不能因本计划存在就视为已获全部后续推送或合并授权。

## 风险与调整条件

| 实际发现                                         | 处理方式                                                                    |
| ------------------------------------------------ | --------------------------------------------------------------------------- |
| 原始适配器操作重建工程、删除 Take 或保留失效片段 | 保留算法，增加受保护的调用和后置校验；不直接将原始 execute 暴露为文件写入口 |
| Node 导入链依赖浏览器全局对象                    | 缩小纯服务边界，或将该能力标记为需要浏览器；不伪造运行环境                  |
| 来源 CLI 与已构建帮助、目标合同不同              | 标注版本与语义差异，逐项适配；不盲目按命令名称复制                          |
| BB 来源、指针或观察轨道无法与编辑结果同步        | 拒绝并列出受影响内容，保留原件与现有工作台限制                              |
| BC 供给／时间／Take 修改使效果或序列目标失效     | 先给出依赖问题；要求明确的后续修正操作，不静默删除绑定                      |
| 新增配置没有现成渲染消费者                       | 保持不可用状态；不得仅新增 JSON 字段就宣布支持                              |
| main 在实施期间新增其他正常更新                  | 重新核对并正常集成；冲突只按实际受影响功能补检查，不覆盖他人提交            |

首轮结束后再按实际依赖和验收速度估算后续工作量。当前不承诺一次短会话完成全部 CLI、50 项 BC 操作及 UI 等价迁移。
