# BC 落消工作流

BC 入口用于展示已有落消工程的编辑、变体和有声导出。它使用当前 `block-crush-drop` 0.4.0 的原生规则、状态哈希、校准帧和 2D 场景，没有复制第二套玩法引擎。

## 打开和保存

从首页选择“打开 BC 落消工作台”，或打开本地地址的 `/#bc`。选择“打开落消示例”可体验一个无需额外文件的三步工程。

“导入工程”接受 `bcs-studio-project` 2.0.0、游戏 `block-crush-drop` 0.4.0 的原生 JSON。当前展示入口支持有 `referenceCalibration` 的 `reference-2d` 工程、30 fps 和不超过 1920 像素的偶数输出尺寸。它不会转换旧格式、其他游戏、镜头后端或帧率。

内嵌 PNG、JPEG、透明 PNG 序列及 PCM WAV 可直接载入。外部引用需要在页面底部选择对应工程目录、CAS 素材库或元素库缓存，再重试导入。只读取用户选择的文件，按路径和 SHA-256 核验；素材缺失、哈希错误或解码失败会报错，不会替换成程序素材。

BC 允许每个所选目录最多 50,000 个文件，只读取当前工程实际引用的字节；BB 既有目录上限保持不变。

“保存 JSON”下载当前可编辑工程并内嵌已解析的附件，不改动输入文件或公共素材库。浏览器发起下载不等于已经确认写盘，请检查下载完成。未保存内容和尚未应用的表单草稿都有离开保护；最近五次成功修改可以撤销。

## 制作外观变体

| 操作         | 行为                                                                                                   |
| ------------ | ------------------------------------------------------------------------------------------------------ |
| 应用配色     | 修改原生颜色身份；绑定图片色板时同时重绘色板，保留透明度与明暗。背景、HUD 和已烘焙序列的像素保持原样。 |
| 程序材质     | 选择柔光倒角、冰晶、立体棱面或木纹星形；明确切回程序牌面，原有图片仍保留在工程附件中。                 |
| 替换背景     | 将所选 PNG/JPEG 绑定到 `world.background`，保留独立的棋盘、牌面及 UI 图集配置。                        |
| 替换牌面材质 | 支持正方形单材质图和按颜色顺序排列的横向图集。单材质图会按现有颜色生成色板，保留明暗与透明度。         |
| 原生碎片形状 | 切换六种常用碎片几何，保留消除时间、原有运动和声音。透明序列仍按已有绑定播放。                         |

牌面图片会供棋盘、候选及拖动使用；碎片纹理由原有几何消费者处理。原生细碎晶片、棱面碎石和圆润碎石可启用牌面纹理；其他形状沿用其原生贴图或程序绘制规则。不能把单一材质替换理解为重新生成整段花瓣等主题序列。

如果原背景图片自身已烘焙棋盘、文字或装饰，替换图片前需准备完整的新背景。页面不会自动分离图片内的像素图层。

## 修改玩法与轨迹

动作表可以修改落位列和落位秒数。内部按 BC 的 30 Hz 规则时钟保存 `impactTick`；已有对应方块轨迹随目标和时间调整，之后重验所有 Take。修改失败会指出 Take 和步骤，原工程不变。

高级编辑提供固定尺寸的 `#` / `.` 初始棋盘和原生 `pieceTracks` JSON。保留的棋盘格身份不变；初始状态和 Take 的引用哈希按原生合同重算。轨迹采用设计画布坐标与秒数，不能套用 BB 的归一化指针坐标。

示例支持有预算的合法路线生成，并保留已有 Take。保存了逐步参考轨迹的工程暂不生成新路线，因为现有轨迹按动作索引关联；这些工程可编辑原有目标和轨迹。当前没有可视拖动录制器、供给图形编辑器或从任意视频自动识别动作的功能。

## 透明序列与声音

已有的 `clearEffectLibrary` 原生效果、逐动作/逐波绑定和 `effect.clear.sequence` 透明序列由当前 BC 场景消费。PNG 序列保留源帧、帧率、哈希和 cue-window 时间关系；它们不是 AE 工程，也不需要 AE 软件。

本入口不包含 AE 适配脚本、历史 Python 批处理或旧主题生成流水线。已有花瓣、萤火虫等序列能随工程播放，但改变消除区域后自动重新生成这些序列尚未接入。

工程自身的音乐、音效、cue、起点、源内偏移、循环和混音参数被保留。可替换内嵌 PCM WAV BGM 并调整增益。连续预览与导出读取同一份混音；暂未新增 MP3/AAC 音频导入或可视音效编辑器。

## 预览与导出

时间线支持定帧、连续播放和 Take 切换。“全程”选中时使用完整 Take；取消后使用保存的选段，避免误把历史选段当完整视频。

预览和导出使用同一个 `BlockCrushDropReferenceScene`。BC 仅适配自己的原生帧，不调用 BB 的玩法或 2D 绘制器；两个游戏共用 `exportFrameVideo` 完成 H.264/AAC MP4 编码和实际编码器的 AAC 时间校准。取消导出、切换工程和页面退出会释放当前资源。

导出需要支持 WebCodecs AVC/AAC 的桌面浏览器。当前不包含 BC 固定镜头、移动镜头或独立 3D 工作台。不能被当前后端消费的镜头或额外 production 配置会被明确拒绝。

## 开发检查

```sh
npm run test:bc
npm run typecheck
npm run build
```

需要检查实际换图、换色、材质、WAV、保存重开和导出时：

```sh
npm run test:browser:bc
```

只检查消除绑定的编辑拒绝和草稿丢弃、恢复行为时，可运行 `npm run test:browser:bc:edits`；该检查不导出视频。

浏览器检查需要本机 Chrome、FFmpeg 和 FFprobe，生成物写入忽略的 `outputs/`。设置 `BC_REAL_PROJECT` 可额外检查本机的完整内嵌 BC 工程；设置 `BC_OUTPUT_DIR` 可指定本机证据目录。测试素材均为程序构造，不上传历史作品、视频、音乐或源素材。

技术测试只覆盖实际执行的示例、资源和编码环境，不等同全部历史作品验收或用户视觉、听感认可。
