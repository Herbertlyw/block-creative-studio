## 验收记录

## 已完成

- BB、BC 的共用分轨编辑器、独立 Take 人声、指定对象压低、严格合同与实际混音消费者；BGM/人声/事件独立修改，保护已有默认和全部未修改声音。详见 [声音混音](AUDIO_MIX.md)。
- 共用导出阶段、最终帧进度、明确错误码、BB 显式取消、两游戏的过期任务隔离和页面退出保护；音频混音可协作让出线程，取消信号传入 AAC 动态校准。CLI 始终输出首帧和末帧，避免阶段日志挤掉短任务的帧进度。
- BB 源时间/测量源帧/校准输出事件帧换算、待确认清单、原始 JSON 及表单的下游确认失效、轨迹折线和点时间关联、错误动作绑定保护、同源视频重新核验、草稿重开及旧生成快照失效。

## 本轮实际验证

验证环境为 Node 24.22.1、Linux、FFmpeg/FFprobe、官方 Chrome headless shell 157.0.8103.50。标准 Chrome 与 Chrome for Testing 均已尝试安装/启动，但宿主禁止 Unix socket，启动报 `socket() failed: Operation not permitted`。官方 headless shell 可以运行界面及 AVC 编码；实测 `AudioEncoder.isConfigSupported` 对 48 kHz、双声道 AAC 返回 `supported: false`。

## 受限、未完成及本机下一步

1. **实际浏览器有声 MP4 与 AAC 校准/取消的端到端验收未完成**，具体阻碍是当前可运行浏览器没有 AAC 编码器。未降级丢弃音轨，也未使用 FFmpeg 另行封装来冒充浏览器导出。请在有 AVC/AAC 的本机 Chrome 上运行上述三个严格有声检查及本轮新检查。
2. **长 BB/BC 有声真实工程未完整验收**。120 秒低分辨率无声压力检查不能替代长工程、全高清、多大素材和目标机器内存压力的验收。当前导出器仍在内存中持有 PCM 与 MP4，没有新增磁盘流式封装。
3. **未进行人工试听，也没有真实参考作品还原验收**。本机需听 BGM/人声/落位/消除的独立增益、压低进入/恢复、相邻与重叠语音、循环接点、片段边界、削波与收尾，核对实际参考视频的帧和轨迹。
4. **BC 参考观察入口未新增**。后续应先定义并接入原生 BC 的列、30Hz impactTick、供给与设计像素轨迹观察合同，再复用通用源身份、草稿和视频时间体验，不能套用 BB 标注字段。
5. 输入为预混 WAV 时仍不能拆分其中的音乐和固定音效；事件 cue 仍不支持源偏移/循环/淡入淡出，MP3/AAC 导入和语音活动检测未实现。以上限制在编辑器和文档中说明。
