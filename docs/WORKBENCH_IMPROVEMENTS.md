## 已完成

- BB、BC 的共用分轨编辑器、独立 Take 人声、指定对象压低、严格合同与实际混音消费者；BGM/人声/事件独立修改，保护已有默认和全部未修改声音。详见 [声音混音](AUDIO_MIX.md)。
- 共用导出阶段、最终帧进度、明确错误码、BB 显式取消、两游戏的过期任务隔离和页面退出保护；音频混音可协作让出线程，取消信号传入 AAC 动态校准。CLI 始终输出首帧和末帧，避免阶段日志挤掉短任务的帧进度。
- BB 源时间/测量源帧/校准输出事件帧换算、待确认清单、原始 JSON 及表单的下游确认失效、轨迹折线和点时间关联、错误动作绑定保护、同源视频重新核验、草稿重开及旧生成快照失效。

- AAC 优先复用原生编码；原生不支持时按需注册固定版本的官方软件 AAC 扩展。软件路径使用同声道/码率的两个独立探针做采样精度动态校准，不写死延迟。音频小段提交避免取消与 worker 初始化竞态；模块准备失败、取消和重试分别验证。

## 本轮实际验证

环境：Node 24.22.1、Linux、FFmpeg/FFprobe、官方 Chrome headless shell 157.0.8103.50。标准 Chrome 与 Chrome for Testing 已尝试启动，但宿主禁止 Unix socket，报 `socket() failed: Operation not permitted`。headless shell 支持 AVC，48 kHz 双声道原生 AAC 探测为 false；本轮通过官方软件 AAC 扩展完成实际有声导出。未用 FFmpeg 重新编码或拼接音轨来替代浏览器导出，FFmpeg 仅用于独立检查。

## 受限、未完成及本机下一步

1. **未进行人工试听，也没有真实参考作品还原验收**。本机需听 BGM/人声/落位/消除的独立增益、压低进入/恢复、相邻与重叠语音、循环接点、片段边界和收尾，并核对真实参考视频的帧与轨迹。
2. **较长测试是合成稀疏动作、约两分钟、中等分辨率**。不代表长真实作品、全高清、大素材量和目标机器内存压力已验收。导出器仍在内存中持有 PCM 与 MP4，没有新增磁盘流式封装；继续用本机真实工程验证。
3. **本环境实际 AAC 输出走软件路径**。原生优先有自动测试，原生 AVC/AAC 浏览器的真实有声回归仍需在本机执行；原生长立体声保留既有内容动态校准。
4. **BC 参考观察入口未新增**。后续须先定义原生 BC 的列、30Hz impactTick、供给和设计像素轨迹观察合同，再复用源身份、草稿和视频时间体验，不能套用 BB 字段。
5. 预混 WAV 仍不能拆分音乐和固定音效；事件 cue 的合同没有源偏移/循环/淡入淡出，因此未加无消费者字段。MP3/AAC 导入、语音活动检测未实现。现有支持与限制已在编辑器和声音文档说明。
